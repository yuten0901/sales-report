# 探索的テストの記録

自動テスト(観点表・プロパティベース)ではカバーしにくい「実際に触ってみないと気づかない」領域を、
セッションベースで手動探索した記録。docs/test-design.md §8「高度な検証手段の全体像」の一環。

---

## セッション1: CLIの基本的な使用感

**チャーター**: 実際のユーザーとして`--help`や基本オプションを触り、案内文・デフォルト値に違和感が無いか確認する。

- `sales-report --help` の表示を確認。オプション名・ヘルプ文・デフォルト値(`--output`の既定`out/summary.md`等)が意図通り表示されることを確認。
- 気づき: 特に問題なし。→ 自動テスト化の必要性は低い(表示内容はTyperのフレームワーク機能に依存する部分が大きいため)。

## セッション2: 「危ないかもしれない」入力パターンを狙い撃ちする

**チャーター**: 設計時に想定していたが自動テストのシナリオとしては書いていない、"人間が思いつきそうな意地悪な使い方"を試す。

| 試したこと | 結果 | 判定 |
|---|---|---|
| `--input`と`--output`に**同じパス**を指定(自己上書き) | 正常終了(exit 0)。**しかし元の入力CSVが集計結果で上書きされ、データが消える** | 🔴**誤判定だった（下記セッション3で訂正）**。クラッシュしないことしか確認しておらず、データが保全されるかは別の観点だった |
| 店舗名フィールドに**カンマを含む値**(`"渋谷店,本店"`)をCSVの引用符付きで入力 | 正しく1つの値として読み込まれ、CSV出力でも引用符付きで正しく再出力される(Python標準csvモジュールの仕様どおり) | ✅安全 |
| CSVに**必須列以外の余分な列**(`memo`など)を追加 | 無視されて正常に処理される(`csv.DictReader`は必須列だけ見る) | ✅安全 |
| **非常に長い店舗名**(90文字程度)を含むデータ | Markdownテーブルとして構文は壊れないが、セルが非常に横長になり見た目の可読性は下がる | ⚠️軽微な観察事項(セキュリティ・機能上の問題ではない。残存リスクに記載) |
| Bashから日本語を含む長い文字列を`printf`で生成しようとした際、**シェル側の文字コード変換で意図せず壊れたファイル**ができた | ツールは想定通りUTF-8/Shift-JISいずれでもデコード不能と判定し、ファイルエラーとして扱い exit 1 で安全に終了(クラッシュしない) | ✅**BV-ENC-04を意図せず実地で再現・確認できた**(偶発的だが有効な検証) |

## セッション3: 自己上書きシナリオの掘り下げ（訂正・2026-07-26）

セッション2で「入力と出力が同じパスでも安全」と結論づけたが、**これは誤りだった**。公開前レビュー（Codex Critical#2）が実機で指摘: 「クラッシュしない」ことしか確認しておらず、**「元データが保全されるか」という別の観点を見落としていた**。実際には`--input X --output X`（または`--output`と`--report-errors`が同一）を指定すると、元の入力CSVが集計結果で正常終了(exit 0)のまま上書きされ、**気づかれないままデータが消える**。

探索的テストの限界がここに表れている: 「動くか」を確認するチャーターだけでは不十分で、「入力に対する副作用が無いか」を明示的にチャーターに含める必要があった。

**教訓**: 探索的テストで「安全」と判定する際は、①クラッシュしないこと ②入力データが変更・破壊されないこと ③出力が期待通りであること、の最低3点を分けて確認する。1点だけ確認して「安全」と結論づけない。

→ **対応済み(FIX-03/DEF-009)**: `cli.py`に入力・出力パスの衝突検知を実装し、衝突時はexit 2で拒否する。回帰テストは`tests/test_cli.py`の`test_fix03_*`系3件。

## まとめ・自動テストへの反映状況

- BV-ENC-04(文字コード判定失敗)は既存の自動テストで意図的にも検証済み。今回の偶発的な発見はその**現実世界での妥当性を裏付けるもの**。
- 自己上書きシナリオは当初「安全」と誤判定していたが、外部レビューで実データ破壊が発覚し、FIX-03として修正・自動テスト化済み（本ドキュメントの誤った結論も本セッションで訂正した）。
