## KI-01: 自動ミューテーションテスト（mutmut）の実行環境適合が未完 — 保留（deferred）

- **状態**: 保留（実験的機能・手動起動専用）。2026-07-27時点。
- **関連**: `docs/defects.md` DEF-023、`.github/workflows/mutation.yml`、`scripts/mutation_score.py`。

### 事象

公開後にCIで`mutation.yml`を初めて実行したところ、mutmutが**全619ミュータントを1件もテストせず**「スコア0.0%」を返していた（当初はワークフローが緑になってしまっていた＝偽陽性）。

### これまでに解消したこと

1. **偽陽性の防止（本質・解消済み）**: スコア集計を`scripts/mutation_score.py`へ切り出してpytestでテスト可能にし、「収集はされたが1件もkilled/survivedの実判定に到達していない（＝計測不成立）」を`MutationCollectionError`として検出し、ワークフローを**正しく赤にする**ようにした。「全件未実行なのに緑」という誤表示は起こらない。
2. **サンドボックスのファイル欠落を2件解消**:
   - `scripts/`がmutmutの`mutants/`サンドボックスのimportパスに無い → `tests/test_mutation_score.py`を`pytest.importorskip`にして、当該環境ではスキップ。
   - `data/`（ゴールデン参照ファイル）が未コピー → `pyproject.toml`の`[tool.mutmut] also_copy = ["data/"]`で追加。

### 未解決（保留理由）

mutmutが`mutants/`サンドボックスで**テストスイートをベースライン実行する際の実行環境差**により、テストが1件ずつ順に失敗して完走できない。判明している順（mutmutは`-x`で1件ずつしか露呈しない）:

1. `test_mutation_score.py`のimport失敗（解消済み）
2. `data/golden/`未コピー（解消済み）
3. `test_output_wiring.py::test_wiring_cli_sanitizes_dangerous_directory_name_in_errors_csv_end_to_end`が、mutmut実行環境下でCLIの終了コードがローカルと異なる（exit 0 期待に対し exit 2）。cwd操作（`monkeypatch.chdir`）や相対パス・テスト実行順序への依存が、mutmutのpytest起動方法と噛み合っていない可能性。
4. （上記の先にさらに残っている可能性あり — `-x`のため未確認）

### なぜ「今は追わない」のか（投資判断）

- **守るべき品質は確保済み**: 「計測が壊れたまま成功扱いになる」という観測可能性の欠陥は修正済み。未完走時は正しく赤になる。
- **通常CIの品質ゲート（テスト/lint/型/カバレッジ/セキュリティ/Pages）は独立して常時緑**であり、mutmutの完走はこれに依存しない。
- **mutmutはローカル（Windows）で実行できない**（`os.fork()`依存）ため、1回の試行がまるごとCI往復になり、環境差の切り分けコストが高い。
- ミューテーション観点の検知力は、当面**手動ミューテーションによる補完的検証**で担保する（下記KI-01補足）。

「試験的ツールの環境適合に際限なく投資するより、主要な品質ゲートを安定運用する方が費用対効果が高い」という判断であり、重大な品質問題（偽陽性）とツール上の残課題を区別した上での**終了条件付きの区切り**である。

### 再開する場合の入口

- mutmut 3.xの`pytest_add_cli_args` / `pytest_add_cli_args_test_selection`で、ベースラインとして実行するテストを絞る（例: 環境依存のE2Eテストをmutmut実行から除外し、`src/`の変異を殺せる単体・配線テストに限定する）。
- または、mutmutの`mutants/`サンドボックス実行に耐えるようE2Eテストのcwd依存を排除する。
- 完走したら、実測ミューテーションスコアを`docs/test-report.md`とREADMEに記載し、`mutation.yml`の閾値ゲートを`continue-on-error`なしで正式化、必要に応じて自動トリガー（push/週次）を復活させる。

### 補足: 手動ミューテーションによる補完的検証（自動mutmutの代わりに実施していること）

- **対象**: 公開前レビューでリスクが高いと判断した箇所 — 金額計算（Decimal）、境界値、CSVインジェクション対策、原子的書き込み、CLI終了コード分岐、文字コードフォールバック、重複明細の合算、集計の並び順、および配線（呼び出し側）。
- **方法**: 対象コードのロジックを一時的に意図的に壊し（変異させ）、テストを実行して失敗する（＝殺せる）ことを確認し、元に戻す。体系的に2回（Opus再確認時の重要箇所8件、FIX-08配線検証で別コンテキストが指摘した生存8件）実施し、いずれも全件検知（8/8・8/8）。加えて各修正でコミット前に赤→緑確認を都度実施。
- **限界**: 手動サンプルは「危険と判断した箇所」に限定され、**自動mutmutが網羅する探索範囲（全619ミュータント）とは異なる**。したがってこれは自動ミューテーションの「代替」ではなく、主要な失敗モードに対する**補完的検証**である。真の網羅的スコアは自動mutmutの完走を要する（本課題）。
