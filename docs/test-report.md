> **教訓**: DEF-004/005/006/007/013(第1弾)はいずれも**自動テスト単体では検知できない種類の欠陥**(CI設定の不整合・ドキュメントと実装の乖離・配線の未検証)であり、カバレッジ100%でも防げなかった。特にDEF-009(データ破壊)・DEF-010(金額誤計算)・DEF-011(秘密漏洩)は実装者自身(Sonnet実装+Opus再確認)が見落とし、外部の別コンテキストレビュー・Codexが発見した。**「多角レビューは自動テスト・単一レビューの代替にならない」**ことを、この成果物自体が実例として証明している。**さらに第2弾では、7件の公開ブロッカーを修正しカバレッジ100%を回復した"直後"の状態に対して重ねてCodexへ再レビューを依頼したことで、DEF-016〜021の6件(金額表示契約・重複ヘッダ・POSIX権限破壊等)が新たに見つかった**。これは「一度レビューを通したから安全」という思い込みへの反例であり、**成果物の性質(金銭を扱う・複数OSで動く・秘密情報を扱う)に見合うレビューの反復には価値がある**ことを示している。**加えてDEF-022は、その第2弾の修正(DEF-016=金額2桁契約)が自ら作り込んだ回帰を、実装後のOpus再確認が捕まえたもの**——「修正がバグを生む」ことすらあるため、修正フェーズにも独立した再確認の目を通す価値があることの実例である。
