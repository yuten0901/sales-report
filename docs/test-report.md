## 4. 検出した不具合

`docs/defects.md`参照。計5件。

- **コード不具合2件**(DEF-001, DEF-002。いずれも全角数字の暗黙受理に起因) — 検出・修正・回帰テスト追加済み。
- **環境制約1件**(DEF-003。mutmutのWindows非対応) — 対応方針を確定。
- **公開前レビューで発見した2件**:
  - **DEF-004(重大度: 高)** ブランチ名`master`とCIトリガー`main`の不一致により、**pushしてもCIが1つも起動しない**状態だった。修正済み(`main`へ統一)。
  - **DEF-005(重大度: 中)** トレーサビリティ表に実在しないテスト関数名が記載されていた。実際の関数名で全面修正し、観点IDによる絞り込み(`pytest -k "EQ-QTY"`)が機能することを検証済み。

> **教訓**: DEF-004/005はいずれも**自動テストでは検知できない種類の欠陥**(CI設定の不整合・ドキュメントと実装の乖離)であり、カバレッジ100%でも防げなかった。「レビューという別の目を通す工程」が自動テストの代替にならないことの実例として記録する。

## 6. リリース可否判断

**条件付きGo**（無条件のGoではない）。

**達成済み**: 計画した全観点(同値分割・境界値・デシジョンテーブル・プロパティベース・ゴールデン・堅牢性・性能・セキュリティ)を実施。行/分岐カバレッジ100%、lint/型チェック全通過、Python 3.11と3.14の両方で全通過、別ディレクトリでの受け入れ検証済み。検出した実バグ(DEF-001/002/004/005)は全て修正済み。

**公開完了とみなすための残条件**（これを満たすまで「品質保証済み」と主張しない）:

1. **CI(`ci.yml` / `security.yml`)が実際に緑になることを目視確認する** — 設定は書いたが一度も動かしていない。DEF-004(ブランチ名不一致でCIが起動しない)が実際に起きた通り、「書いた」と「動く」は別物。
2. **`mutation.yml`を実行し、ミューテーションスコアの実測値を取得してREADMEに記載する** — 設計時の完了基準であり、現状は手動サンプル8/8で代替している状態。
3. **GitHub Pagesのカバレッジレポート公開が機能することを確認する**（リポジトリ設定で Pages の Source を "GitHub Actions" に設定する必要がある）。

上記1〜3が未了の状態でも、コード品質・テスト設計・ドキュメントは公開に足る水準にある。ただし**READMEのバッジは公開直後は「一度も成功していないCI」を指す**ため、CIを緑にするまではバッジが赤/不明表示になる点を認識しておく。

> この「条件付きGo」という結論自体が、テスト完了報告書の役割そのもの——「どこまでやったか」ではなく**「何が残っているかを言えること」**——の実践例である。
